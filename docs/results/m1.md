Git Bash. Tools: OPA 1.21.1, conftest 0.71.1 and Terraform 1.16.5 (release binaries downloaded by

    ::notice title=policy e2e::compliant plan passed all 6 rules; non-compliant plan blocked with exactly the 11 expected violations

- The compliant example exercises the cases most likely to cause false alarms: two buckets from a
  module called with `for_each`, a Deny statement with `Principal: "*"`, HTTPS open to the
  internet, SSH from the VPC range, PostgreSQL from a security group, egress to everywhere, and
  tags that come only from the provider's `default_tags`. 0 violations.
- The non-compliant example also contains HTTPS from the internet; it is correctly not reported.
- The script fails unless conftest evaluated all 6 rule packages, the compliant plan has exit 0
  and no messages, the non-compliant plan has exit 1, and its messages equal
  `examples/noncompliant/expected-violations.txt` line for line.
- **The gate catches a broken rule.** With a copy of the policies in which PAC003 only treats
  `0.0.0.0/0` as the internet, the same script exited 1: the diff showed the missing
  `aws_security_group_rule.rdp ... ::/0` line and printed
  `::error title=policy e2e::the non-compliant plan's violations differ from examples/noncompliant/expected-violations.txt`.
- **No AWS call was made.** Both plans ran with placeholder keys, no AWS profile or token, EC2
  metadata off, and `HTTPS_PROXY`/`HTTP_PROXY` pointing at a closed local port; they succeeded,
  so the provider did not reach any endpoint.

## Security update (2026-10-15)

The first CI run on GitHub failed `make audit`: govulncheck (binary mode) reported 10 standard-library advisories published 2026-10-08 (GO-2026-6599, 6600, 6603, 6605, 6607, 6608, 6610, 6611, 6612, 6613) in the OPA 1.21.1 binary, which was built with an affected Go release. OPA was upgraded to 1.21.2, whose release binary is built with Go 1.27.2 (read from the binary's build info), and both SHA-256 pins in `scripts/tools.sh` were updated from the published `.sha256` files. Rerun on this machine with OPA 1.21.2: `opa fmt` and `opa check --strict` clean, unit tests 56/56 passed, 12 of 12 mutants killed, and the end-to-end check passed (compliant plan passes all 6 rules; non-compliant plan blocked with exactly the 11 expected violations). The sections above record the original run with OPA 1.21.1.

The next CI run then failed on the same advisories (plus GO-2026-6609 and GO-2026-6617) in conftest 0.71.1, Terraform 1.16.5 and hashicorp/aws 6.67.0, and GO-2026-6604 in their Windows builds. No release of those tools is built with the fixed Go yet (Terraform 1.16.6 is built with Go 1.26.8; aws 6.68.0 was published on 2026-10-07), so the audit was changed to accept an ID per binary instead of for every binary, and the 13 IDs were accepted for conftest, terraform and terraform-provider-aws only, with the reason in `scripts/audit-accepted.txt` (local plan JSON and offline plans, no untrusted network input). OPA stays clean, so any new finding in it still fails the build. govulncheck now runs with Go 1.26.9. `make audit` on this machine: opa clean, every other finding accepted for its binary, no stale entries.
